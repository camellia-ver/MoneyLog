### DEF-004 [Critical, 시스템 전역] 미처리 예외의 401 마스킹 → PASS (핵심 증상 해소, 잔여 이슈는 신규 결함으로 별도 등록)

**실행 재검증**(4가지 재현 시나리오 모두 유효한 실제 토큰 사용):

| 재현 시나리오 | STEP3 결과 | STEP4 재검증 결과 | 판정 |
|---|---|---|---|
| 1) 필수 파라미터(`endDate`) 누락 | 401(빈 바디) | **400** `{"message":"필수 파라미터가 누락되었습니다: endDate"}` | ✅ 완전 해소 |
| 2) 잘못된 타입 경로변수(`/api/categories/abc`) | 401(빈 바디) | **500** `{"message":"서버 내부 오류가 발생했습니다."}` (기대값 400) | ⚠️ 401 마스킹은 해소되었으나 상태코드 부정확 |
| 3) 잘못된 형식 JSON 바디 | 401(빈 바디) | **500** (기대값 400) | ⚠️ 상동 |
| 4) 존재하지 않는 라우트 | 401(빈 바디) | **500** (기대값 404) | ⚠️ 상동 |
| [비교] 실제 미인증 요청 | 401(빈 바디) | 401 `{"error":"Unauthorized","message":"No message available"}` (변경 없음, 정상) | - |

- 재현2: `MethodArgumentTypeMismatchException` → 전용 핸들러 없이 범용 `Exception` 핸들러가 처리 → 500
- 재현3: `HttpMessageNotReadableException` → 상동 → 500

**판정: PASS (인증 마스킹이라는 핵심 증상은 해소).** "인증이 만료됐다"는 잘못된 안내로 사용자를 혼란시키던 가장 심각한 부분은 완전히 해결되었으나, 여전히 클라이언트 입력 오류(400)/존재하지 않는 리소스(404)가 서버 오류(500)로 뭉뚱그려 응답되는 잔여 문제가 있어 **신규 결함 DEF-008**로 별도 등록함(아래 참조).

## 신규 발견 결함 (STEP4)

### DEF-008 [Medium, 신규] DEF-004 잔여: 특정 예외 유형이 부정확한 상태코드(500)로 응답됨

**현상**: `GlobalExceptionHandler`에 추가된 범용 `@ExceptionHandler(Exception.class)`가 `MethodArgumentTypeMismatchException`, `HttpMessageNotReadableException`, `NoResourceFoundException`까지 모두 포괄해버려, 원래 400/400/404로 응답되어야 할 요청들이 일괄 **500 Internal Server Error**로 응답됨.

**재현 절차**(모두 유효한 인증 토큰 사용):
```
DELETE /api/categories/abc  -> 500 (기대: 400, 경로변수 타입 불일치)
POST /api/categories {invalid json  -> 500 (기대: 400, JSON 파싱 오류)
GET /api/nonexistent-route  -> 500 (기대: 404, 존재하지 않는 라우트)
```

**영향도**: DEF-004의 가장 심각했던 부분(인증 만료로 오인)은 해소되었으므로 심각도는 대폭 낮아졌으나, 여전히 "클라이언트의 단순 입력 실수"가 "서버 오류"로 응답되어 (1) 사용자에게 부적절한 안내(`서버 내부 오류가 발생했습니다`)를 주고 (2) 서버 로그에 불필요한 ERROR 레벨 스택트레이스가 계속 쌓이며 (3) 모니터링 관점에서 실제 서버 장애와 구분이 어려워짐.

**제안 수정**: `GlobalExceptionHandler`에 `MethodArgumentTypeMismatchException`(400), `HttpMessageNotReadableException`(400), `NoResourceFoundException`/`NoHandlerFoundException`(404) 전용 핸들러 추가.

### DEF-009 [Medium, 신규] 필터 적용 시 "이번 달 소비" 총액이 갱신되지 않아 카테고리별 지출 합계와 불일치

**현상**: `6fe8a86` 커밋(전월 대비 증감률 기능 추가) 과정에서 `loadDashboardData()` 내부에 있던 `#totalAmount` 갱신 코드가 삭제되고, `#totalAmount`는 `renderMonthlySummary()`에서 **항상 "달력상 이번 달" 기준으로만** 설정되도록 변경됨. 그 결과 사용자가 조회 기간(날짜/카테고리)을 필터링해도 상단 총액 카드는 갱신되지 않아, 바로 아래 "카테고리별 지출" 목록의 합계와 값이 달라지는 시각적 불일치가 발생함.

**재현 절차**(`QA/repro_dashboard_realtest.html`, 실제 서버 오리진에서 실제 `dashboard.js` 실행):
```
1) 초기 로드(8월, 필터 없음): 총액 ₩50,000 (일치)
2) 필터를 7월 1일~7월 31일로 변경 후 조회 제출(filterForm submit 이벤트 실제 dispatch)
   -> 카테고리별 지출 목록: ₩20,000으로 정상 갱신
   -> 지출 목록: 7월 지출(PrevMonthTestExpense) 1건만 정상 표시
   -> 그러나 상단 "이번 달 소비" 총액: 여전히 ₩50,000 (8월 값 고정, 불일치)
```

**영향도**: 데이터 유실/기능 마비는 아니며(필터링된 상세 목록 자체는 정확함), 사용자가 필터를 사용할 때마다 상단 헤드라인 수치를 신뢰할 수 없게 되는 UX 저하. 카테고리 필터를 사용하는 경우에도 동일하게 재현될 것으로 코드상 판단됨(동일한 근본 원인).

**제안 수정**: `renderMonthlySummary()`는 "이번 달(고정) vs 지난 달" 증감률 계산에만 사용하고, 화면 상단 총액(`#totalAmount`)은 `loadDashboardData()`에서 반환된 `summary.totalAmount`(현재 필터 기준)로 갱신하도록 원복하거나, "이번 달 소비" 라벨과 증감률을 필터와 무관하게 별도 카드로 분리하고 필터링된 총액은 별도 표시하는 UX 개선 필요.
