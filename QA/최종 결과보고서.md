### Sign-off 판정: **Go (조건부 아님, 정식 합격)**

Critical·High 등급 결함이 **모두 해소**되었으며(4건 Critical → 4건 모두 PASS 재확인), 잔존하는 결함은 전부 Medium/Low 등급으로 **Sign-off 조건(Critical/High 0건)을 충족**함. 다만 Medium 등급 미해결 4건(DEF-005, DEF-006, DEF-008, DEF-009)은 배포 전 또는 차기 스프린트에서 후속 조치를 권고하며, 이 조건 하에서의 **조건부 합격이 아닌 정식 Go 판정**임을 명시함(Medium/Low는 정책상 Sign-off를 막지 않음).

잔여 Blocked 2건은 결함이 아닌 **테스트 환경/도구 제약**임:

## 5. 회귀(Regression) 영향도 확인

이번 STEP4에서 수정된 코드(`UserService`, `GlobalExceptionHandler`, `SecurityConfig`, `CategoryRepository`, `ExpenseRepository`, `auth.js`, `dashboard.js`)와 인접한 기존 Pass 시나리오를 재확인함:
- 카테고리명 중복 생성 시 409 Conflict — 회귀 없음
- 타 사용자 리소스 접근 시 403 Forbidden — 회귀 없음
- `/error` 경로를 `permitAll`에 추가했음에도 실제 보호 엔드포인트(`/api/categories`, `/api/users/me` 등)는 토큰 없이 여전히 401 — 보안 우회 없음 확인
- 회원 탈퇴 cascade 수정 후 삭제된 사용자 소유가 아닌 다른 사용자의 category/expense 행 수(전체 카운트) 이상 없음 확인

## 6. Sign-off 서명

| 항목 | 내용 |
|---|---|
| 판정 | **Go (정식 합격)** |
| 판정 사유 | Critical 4건/High 0건 결함이 모두 해소되어 Sign-off 조건(Critical·High 미해결 0건)을 충족함 |
| 잔존 리스크 | Medium 4건(DEF-005, DEF-006, DEF-008, DEF-009), Blocked 2건(환경 제약) — 서비스 출시를 막을 수준은 아니나 후속 스프린트에서 조치 권고 |
| 권고 사항 | ① DEF-009(신규 회귀)는 최근 추가 기능으로 인한 것이므로 우선순위를 높여 조속히 수정 권고 ② DEF-008은 GlobalExceptionHandler에 개별 예외 핸들러(400/404) 추가로 간단히 해결 가능 ③ DEF-005(로그인 시도 제한), DEF-006(Swagger 운영 노출)은 실제 운영 배포 전 반드시 조치 필요 |
| Sign-off 이후 유의사항 | 본 Sign-off 이후 코드 변경이 발생하면 STEP3(결함 등록/테스트 수행)부터 재시작해야 함(QA 운영 규칙) |
